# 验收输入脚本说明

这些 `.txt` 是喂给程序的**标准输入**（不是配置文件）。程序只从 stdin 读数据，**每个提示都必须按顺序对应一行**，
多一行少一行都会错位。运行方式（在仓库根目录）：

```powershell
New-Item -ItemType Directory -Force out | Out-Null
cmd /c "run.bat < test-inputs\building.txt > out\building.log 2>&1"
Get-Content out\building.log -Encoding UTF8
```

## 通用规则

- 每个脚本开头固定两行 `admin` / `123456`（登录），结尾固定 `6`（退出系统）。
- 脚本**有状态**：依赖 `db/schema.sql` 的示例数据与固定 id（楼栋 1/2、房间 1..6、床位 1..24、学生 2025001..2025005）。
- **重跑任何脚本前先重置数据库**（自增 id 不回退，否则断言会失败）：
  ```powershell
  $env:MYSQL_PWD="123456"
  cmd /c "mysql --host=localhost --user=root --default-character-set=utf8mb4 < db\schema.sql"
  ```
- 文件必须 **UTF-8 无 BOM**。PowerShell 5.1 的 `Set-Content -Encoding UTF8` 会写入 BOM，
  会让第一行变成 `\uFEFF6` 导致解析失败；需要生成时用
  `[System.IO.File]::WriteAllText($path, $text, (New-Object System.Text.UTF8Encoding($false)))`。

## 各脚本

| 脚本 | 覆盖内容 | 关键期望输出 |
|---|---|---|
| `skeleton.txt` | 骨架菜单 + 退出 | 主菜单、`谢谢使用` |
| `login.txt` | 登录成功 | `登录成功` |

| `building.txt` | 楼栋增删改查 + 重名 + 不存在 | `新增成功`、`该楼栋名称已存在`、`修改成功`、`该楼栋不存在`、`删除成功` |
| `room.txt` | 房间自动生成床位/重复房号/扩容缩容/停用床位/删房间 | `新增成功, 已自动生成3个床位`、`该楼栋下已存在房间:101`、`调整成功`×2、`操作成功`×2、`删除成功` |
| `building-guard.txt` | 删除有房间的楼栋被拒 | `该楼栋下还有3个房间, 请先删除房间` |
| `student.txt` | 学生增删改查 + 非法年龄重试 | `请输入 10~100 之间的数字`、`新增成功`、`该学号已存在`、`修改成功`、`该学号的学生不存在`、`删除成功` |
| `stay.txt` | 入住（成功/重复/性别不符/床位被占）+ 退住 | `办理入住成功`×2、`该学生已入住1号楼101房1床, 请先办理退住`、`性别与楼栋不符, 不能入住`、`该床位已被占用`、`该学生当前未入住, 无需退住`、`办理退住成功` |
| `stat.txt` | 查询统计 5 项 | `空床位数:23`、`流水条数:3`、`住宿位置:2号楼201房1床` |
| `../test_input.txt` | 全流程 8 阶段 + 16 个反例（正式验收脚本，161 行） | 见下表与实现计划 Task 11 |

> `stat.txt`、`stay.txt` 等脚本的期望值依赖执行 Task 9 之后的库状态（赵敏住 2号楼201房1床、3 条流水）；
> 单独重跑请先按上面的规则重置数据库，再从 `test_input.txt` 跑一遍，或按各自任务章节的说明执行。

## `test_input.txt` 阶段划分（共 161 行）

约定：**阶段的第一行是进入该阶段主菜单的那一行**（例如楼栋阶段从主菜单选 `1` 开始）。

### 跨阶段依赖（改脚本时必须一起考虑）

- 阶段 C 停用的**床位 26** 是阶段 E「`该床位已停用, 不能分配`」的触发点。
- 阶段 C 新建并在阶段 F 删除的**房间 104**、阶段 F 把 **101 扩到 5 床**，共同保证终态
  `t_bed 行数 == sum(t_room.capacity) == 25`。
- 硬编码的 id（床位 `2`/`4`/`13`、房间 `7`、楼栋 `9999`）依赖 `schema.sql` 的固定示例数据 id；
  这也是「重跑前必须重置数据库」的原因。
- 终态断言（反例关键字、SQL 一致性、`bed_id 非空 ⟺ 最后一条流水是入住`）见实现计划 Task 11 步骤 3–8。
